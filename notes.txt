# First we have to configure the actuator endpoints in the microservices so that prometheus can collect data. We have to configure prometheus to collect metrics and configure the prometheus configuration yml file to collect data from the url exposed from the microservices. Like for order-service - the endpoint will be http://url/order-service/actuator/. In grafana, we can configure dashboards to collect data through prometheus and display the metrics.

# Distributed tracing - A way to track requests as they move through different services in a microservice architecture. This can be done by Zipkin.

# API Gateway - Create a gateway service in which configure the properties file. And configure in such a way that when the
api request starts with for eg "/api/users" then it should go to user service. So to configure it, specify the service name in id,
the uri of the service and then the predicate in which the condition will be present.

# Product Service
spring.cloud.gateway.routes[0].id=product-service
spring.cloud.gateway.routes[0].uri=http://localhost:8081
spring.cloud.gateway.routes[0].predicates[0]=Path=/api/products/**

# User Service
spring.cloud.gateway.routes[1].id=user-service
spring.cloud.gateway.routes[1].uri=http://localhost:8082
spring.cloud.gateway.routes[1].predicates[0]=Path=/api/users/**

# GlobalFilter - for filtering requests within the gateway
# RequestFilter - for filtering web requests within the whole application.

# Rewrite path - by using rewrite path we can modify the endpoint of the api but it will be modified on the RouteLocator
. It will just manipulate the path.
